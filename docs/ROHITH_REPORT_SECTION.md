# Setup and implementation

We implemented sequential factual editing using the official ROME implementation and GPT-2 XL. Model and ROME source revisions are pinned, with float32 weights, eager attention, and the official GPT-2 XL hyperparameters targeting MLP layer 17. An isolated Python 3.11 environment separates experimental dependencies from Colab's notebook interpreter. The pipeline downloads CounterFact and the official covariance statistics automatically, and evaluates at most four prefixes per forward pass to limit GPU memory use.

Groups contain two to four CounterFact records for the same subject, identified by case ID and checked for distinct relations. The runner supports the supplied sequence and its reverse. Each group/order starts from original weights. All group facts are evaluated before editing and after every edit, while independent single-edit controls start from the same original weights. Editable weights are restored in a finally block and checked for exact equality. Both orders reuse persisted context templates; each edit uses seed 32 plus its case ID.

For every evaluated rewrite, paraphrase, neighborhood, and attribute prompt, the pipeline records the old and new target mean token negative log-likelihoods. The reported P(old) and P(new) values are their exponentials with negated sign, representing geometric-mean token probabilities rather than joint sequence probabilities. Efficacy and paraphrase success prefer the new target; neighborhood success prefers the original target. Strict comparisons preserve the official scorer's treatment of ties. First-edit loss is counted only when that edit succeeded initially and failed after subsequent edits. Both unconditional and eligible-edit denominators are retained.

A dedicated CPU verifier checks group identity, stage and prompt coverage, probability conversions, recomputed metrics and retention flags, and run/source fingerprints. Results are written atomically after successful validation. Resume validates completed records and rejects changed configuration, groups, source, or environment. Live progress identifies the group, order, and editing stage. Exact sources and input metadata accompany every exported run.
